# Deploying the 2026-08 release

Step-by-step for the six commits on `rbac-page-ownership-and-build-fix`.
Assumes the VPS is already set up per [VPS-DEPLOYMENT.md](./VPS-DEPLOYMENT.md);
this covers only what *this* release needs.

Read section 0 first. Two steps here are ordering-sensitive and one is
destructive if skipped.

## 3. Backend — migrate BEFORE restarting

Order matters. The new code queries `ExamNotification.sortOrder`; if the
process restarts before the column exists, exam notifications return 500 until
the migration lands.

```bash
cd /var/www/ksrm && git pull
cd backend
npm ci
npx prisma migrate deploy      # adds 20260813120000_exam_notification_sort_order
npx prisma generate
npm run build
pm2 restart ksrm-api
pm2 logs ksrm-api --lines 40   # expect "Nest application successfully started"
```

The migration is `ADD COLUMN "sortOrder" INTEGER NOT NULL DEFAULT 0` — additive,
non-breaking, and safe to re-run. Every existing row gets 0 and stays tied, so
the previous date ordering still decides until someone drags something.

**`npx prisma generate` fails with EPERM if the API is still running.** Stop it
first (`pm2 stop ksrm-api`) if you hit that, then start it after.

Check the new routes are mapped and guarded:

```bash
curl -s -o /dev/null -w "%{http_code}\n" -X PATCH https://api.ksrmce.ac.in/api/exam-notifications/reorder
curl -s -o /dev/null -w "%{http_code}\n" -X DELETE https://api.ksrmce.ac.in/api/news/1/permanent
```

Both must print **401** (route exists, auth enforced). A **404** means the build
did not pick up the new code.

## 4. Nginx — the two config files

Do this **before** the frontend rebuild if you want to verify gzip immediately
after; the order does not otherwise matter.

### 4a. Certificate must cover both hostnames

Run this *first*. A browser validates the certificate **before** it sees any
redirect, so a www-only-uncovered cert fails before the 301 can happen.

```bash
sudo certbot --nginx -d ksrmce.ac.in -d www.ksrmce.ac.in
```

### 4b. Install the configs

```bash
sudo cp deploy/nginx-performance.conf   /etc/nginx/snippets/ksrmce-performance.conf
sudo cp deploy/nginx-redirects.conf     /etc/nginx/snippets/ksrmce-redirects.conf
sudo cp deploy/nginx-canonical-host.conf /etc/nginx/sites-available/ksrmce-canonical-host.conf
```

`nginx-performance.conf` needs a `map` at `http {}` level (not inside
`server {}`) — it is written at the top of that file:

```nginx
map $http_accept $webp_suffix {
    default  "";
    "~*webp" ".webp";
}
```

Then, inside the **existing** server block for the site:

```nginx
server {
    server_name ksrmce.ac.in;          # apex ONLY - not www
    root /var/www/ksrm/out;

    include /etc/nginx/snippets/ksrmce-performance.conf;
    include /etc/nginx/snippets/ksrmce-redirects.conf;
    ...
}
```

> **Check `server_name` carefully.** If it still reads
> `server_name ksrmce.ac.in www.ksrmce.ac.in;` then the www redirect block will
> never be reached, because this block already matches www.

Enable the redirect site and reload:

```bash
sudo ln -sf /etc/nginx/sites-available/ksrmce-canonical-host.conf /etc/nginx/sites-enabled/
sudo nginx -t          # MUST pass before reloading
sudo systemctl reload nginx
```

`nginx -t` failing with *"unknown directive brotli"* means the module is not
installed — the brotli block in the performance file is commented out by
default, so uncomment it only after installing `libnginx-mod-brotli`.

## 5. Frontend

The build now contacts the API to read department SEO overrides. It is wrapped
in a catch, so a down API will not fail the build — but overrides will be
skipped, so bring the backend up first (§3).

```bash
cd /var/www/ksrm/frontend
npm ci
cat .env.local            # NEXT_PUBLIC_API_URL must be https://api.ksrmce.ac.in
npm run build
```

**Verify before publishing** — these catch the two mistakes that have shipped
before:

```bash
npm run seo:audit                                  # must print 21/21, 0 critical
grep -rl "localhost:4000" out/_next | head -1      # must print NOTHING
grep -rl "api.ksrmce.ac.in" out/_next | head -1    # must print a match
```

If `localhost:4000` appears, `.env.local` was not read — every image and PDF
would resolve against the visitor's own machine. Fix and rebuild; do not publish.

Then publish:

```bash
rsync -av --delete out/ /var/www/ksrm/out/
```

`--delete` is intentional: `/test/` and the eight department alias pages must
disappear, or they stay live as indexable duplicates.

## 6. Database checks — read before acting

These are **checks**, not changes. Run the SELECTs; only act if the answer says so.

### 6a. Are the offices present?

Without them, Library and the Examination Section have no admin workspace and
the Controller of Examinations block renders nothing.

```sql
SELECT slug, name FROM "Department"
 WHERE slug IN ('central-library','examination-section');
```

Two rows → nothing to do. Empty → import them (guarded, safe to re-run):

```bash
psql -U ksrm -d ksrm_db -f import-library-exam-staff.sql
```

### 6b. Are file URLs machine-locked?

```sql
SELECT count(*) FROM "Download" WHERE "fileUrl" ~ '^https?://';
```

**0 → nothing to do.** Anything else means those documents carry an absolute
host in the database. On the machine they were imported on they work; anywhere
else the link points at the visitor's own computer and the download breaks.

I only ever saw the local development database, where 7,186 rows carried
`http://localhost:4000/...`. Production may already be clean — check before
assuming. If it is not:

```bash
cd frontend && node scripts/exam-docs-dryrun.mjs --sql review.sql
# READ review.sql, then run it yourself after the backup in §2
```

### 6c. Cosmetic, your call

1,927 documents carry `groupLabel = 'Legacy uploads (demo1)'`, and `groupLabel`
renders as a **visible heading on public pages** — 338 are live, including 183
on the Examinations results section. Visitors see an old-site name.

```sql
-- Preview first:
SELECT count(*) FROM "Download" WHERE "groupLabel" = 'Legacy uploads (demo1)';
-- Then, if you want it renamed (a rename, nothing is deleted):
UPDATE "Download" SET "groupLabel" = 'Archive'
 WHERE "groupLabel" = 'Legacy uploads (demo1)';
```

## 7. Verify the live site

```bash
# www must 301 to apex, one hop, same path
curl -sI https://www.ksrmce.ac.in/departments/cse/ | grep -iE '^HTTP|^location'

# JS must be gzipped AND immutably cached
curl -sI -H 'Accept-Encoding: gzip' \
  "https://ksrmce.ac.in$(curl -s https://ksrmce.ac.in/ | grep -o '/_next/static/chunks/[^\"]*\.js' | head -1)" \
  | grep -iE 'content-encoding|cache-control'

# Homepage: exactly one h1, real numbers not zeroes
curl -s https://ksrmce.ac.in/ | grep -c '<h1'                    # 1
curl -s https://ksrmce.ac.in/ | grep -o 'stat-number">[^<]*<' | head -3

# Robots and sitemap
curl -s https://ksrmce.ac.in/robots.txt
curl -s https://ksrmce.ac.in/sitemap.xml | grep -c '<loc>'       # 69

# A removed page must now 404
curl -s -o /dev/null -w '%{http_code}\n' https://ksrmce.ac.in/test/     # 404
```

Expected: `301` + `location: https://ksrmce.ac.in/departments/cse/`,
`content-encoding: gzip`, `cache-control: public, immutable`, `1`, real
figures (`46`, `35.23`, `1,200`), `69`, `404`.

## 8. If something is wrong

```bash
git log --oneline -6          # commits are split by area
git revert <sha>              # revert just the offending one
cd frontend && npm run build && rsync -av --delete out/ /var/www/ksrm/out/
```

The migration is additive with a default — leave it in place; it breaks nothing
if the code is rolled back.

To restore the database from §2:

```bash
psql -U ksrm -d ksrm_db < ~/ksrm_db_<timestamp>.sql
```

## 9. After deploying — Search Console

Do this **after** §4, or you will register duplicate-host problems that the
redirect has already fixed.

1. Verify `ksrmce.ac.in`, `www.ksrmce.ac.in` and a Domain property.
2. Set `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION` in `.env.local` and rebuild — the meta tag is already wired and emits nothing when unset.
3. Submit `https://ksrmce.ac.in/sitemap.xml`.
4. Watch **Page indexing → Duplicate, Google chose different canonical**. The nine leadership/placements pages that were canonicalised to their parents should drop out of that report as they are recrawled.

Expect **weeks, not days**, for this to show up.
